**과열 만석 정책 사용자 승인:** 사용 가능한 일반 1칸을 과열 1칸으로 치환하며 총 점유를 유지한다. 예: 일반50 → 일반49+과열1. 이미 다른 공격이 확보한 스택은 바꾸지 않는다. 별도 과열 보관함이나 51번째 칸은 만들지 않는다.

[수정과 검증](../../outputs/new-choice-fixes-20261104/RESULT.md).

- 미정 밸런스 수치는 에이전트가 SO에 임시값으로 넣어 진행한다. 수치를 정하지 않았다는 이유만으로 구현을 보류하지 않는다. 임시값은 최종 밸런스 확정과 구분한다.
- **C02 가속 운전 (타이머 10% 추가 소모와 공속 증가):** 타이머가 흐르는 동안 계속 적용되는 패시브다. 마지막 잔액을 보호하거나 추가 소모를 생략하는 별도 예외는 없다. 실제 전투 경과 dt는 유지하고 남은 시간 감소만 1.1배로 계산한다. 0초 도달은 일반 종료/시간 금고 계약을 따른다.
- **C03 제물 (처치 보상 후 10초를 지불하고 공격력 +2%):** 실제 처치 보너스 +30초를 받은 직후 -10초를 자동 지불한다. 이를 +20초 한 건으로 합치지 않는다. +30과 -10을 각각 보여주는 것은 사용자 지정 연출 의도다. 이 정상 흐름에서 별도의 잔여 시간 부족 질문은 필요하지 않다.
- **C06 시간 금고 (런 1회 15초 유예와 임시 Legend):** 유예 시계는 보스가 죽은 후 다음 보스 등장 전의 3초 대기에서만 멈추고 나머지는 계속 흐른다. 플레이어 조작은 햄버거 메뉴의 딜표와 설정창만 허용한다(11-04 사용자 확정). 강화창 진입과 강화 결제, 출격, 판매, 합성, 유닛과 토템의 클릭/이동/회전, 족장 스킬, 토템 보관함과 획득 선택지 창 진입을 막는다. 유예 시작 시 진행 중인 드래그는 취소하고 열려 있던 강화창도 닫는다. 차단 연출은 후속으로 제작한다. 레벨업/승천 선택과 토템 보상도 제시하지 않으며, 선택 UI를 기다려 다음 보스 진행이 멈추지 않도록 한다. 이 3초는 현재 GameConfig.bossSpawnDelaySeconds=3인 구간을 가리킨다. 그 외 개별 연출을 이유로 유예 시계를 정지하지 않는다.

위 구현 반영과 별도로 아래의 과거 제안/후보는 자동 채택하지 않았다. 반응3종의 운영 카드 편입도 이후 완료했으며 문서 맨 위 최신 상태를 따른다.

## 1. 컨셉과 범위

**[확정] 주 컨셉 = 자폭 / 해킹 / 오버드라이브. 편대 사격 컨셉은 폐기.** 기존 공격·카드 코드를 일괄 삭제한다는 뜻은 아니다. 젤탕 경제와 알팡 독립 액티브는 어떤 컨셉에서도 쓰는 **드론 덱 공용 층**이다. 알팡은 그리드 유닛이 아니다.

오버드라이브는 **시간을 태워 다른 것을 산다**. 슬레이 더 스파이어 아이언클래드의 체력 소비 계열(제물/사혈/파열)을 시간으로 옮긴 방향이다. 남은 생존 시간을 화력·합성·해킹 효율에 투자하고, 디시그망의 회복을 연료로 쓴다. 참고 게임의 동명 효과를 그대로 복제한다는 뜻은 아니다.

**디시그망:** 공격력은 베탕 수준 유지, 시간 회복 상한·감쇠 없음. 무한 방지는 느린 공속과 충전 공격 횟수로 조정하며 수치는 실측 후 정한다. 현행 본체6공격/빈도0.33/회복0.3초와 공격력은 테스트값이다. 베탕 수준이라는 방향을 새 등급별 수치로 임의 환산하지 않는다. 드론0의 공용 엔진 기여 제외는 유지한다. 과거 공속2배 예시나 HP 복리는 전체 조합의 안전성 증명이 아니다.

**삭제:** 배수진, 봉인 해제. (파열식 공격력은 2026-11-03 오류 누적으로 되살림, §1.1) 기존 기각 긴급 출격·시간 저당도 되살리지 않는다. 명시된10초/15초/0.5초/10%/5개/7.5개분은 확정 규칙이며 임의 변경하지 않는다. 제물은 회당 공격력 +2%로 확정했다(2026-11-03). 운영8장의 등급과 나머지 수치는 사용자 위임에 따라 저작 완료했고 임시 밸런스와 최종 실측값을 구분한다(§10 Q19). 미채택 후보의 X/N은 현재 구현 대기 질문이 아니다.

### 1.1 글리치 트리거 [확정, 2026-11-03]

- **글리치** = 카드나 유닛 효과로 남은 시간이 **늘거나 줄었을 때** 발생하는 트리거. 보스 처치 보너스 시간과 자연 감소는 포함하지 않는다. 시간 금고 유예 15초 동안 막힌 회복도 글리치가 아니다(시간이 실제로 바뀌지 않음).
- 반응 카드는 들고 있으면 자동 발동한다. 버튼과 판단 피로를 늘리지 않는다(보스 패턴이 많음).
- 카드 문구에 "글리치" 용어는 늘거나 줄 때 **둘 다** 발동하는 카드에만 쓴다. 한쪽만 발동하면 조건을 직접 쓴다. 테마 분류는 모두 글리치. 카드/용어 문구는 효과 확정 뒤 별도로 정한다.
- 설계용 분류(플레이어 비노출): 원천 = 시간을 실제로 바꾸는 효과(디시그망 회복, 제물, 과부하 합성, 과열 압축). 가속 운전은 시간을 직접 더하거나 빼지 않으므로 원천이 아니다. 시간을 늘리는 원천은 디시그망뿐이다.
- **§2-4(소비 보상은 낸 초 수 비례, 횟수로 이득 없음)는 아래 반응 카드에 적용하지 않는다.** 반응 카드는 글리치 **횟수**마다 발동한다(사용자 결정). 원천이 고정된 카드 이벤트라 플레이어가 임의로 쪼갤 수 없다.

### 1.2 초기 구현 범위 (2026-11-03 당시 기록)

아래 미구현/운영30장 표기는 당시 상태다. 현재는 문서 맨 위와 §10을 따른다.

사용자 결정: 확정된 글리치 감지와 반응 3종부터 구현하고 미정 동작은 대기한다. C10 복구 패킷은 회복 1회당 해킹 스택 **1개**로 확정했다.

- 디시그망의 실제 시간 회복을 `TimerController.AddTimeFromDisigman`에서 원인 유닛과 보스에 귀속한다. 기존 표시용 `TimeAddSource.Hack`만으로는 글리치를 만들지 않는다.
- `RecoveryHackingDefinition`, `GlitchBombDefinition`, `GlitchAttackDefinition`을 현행 조합형 선택지 경로에 연결했다. 복구 패킷은 델탕 없이도 공유 해킹 원장을 사용하고, 소각 신관은 베탕 없이 원인 유닛의 공격력으로 공유 자폭 프리팹을 발사한다. 오류 누적은 공격력 기반 피해와 표시값에 한 번 적용하며 고정 피해를 제외한다. 적립은 획득 후부터, 최대 1000회이며 새 런에서 초기화한다.
- **반응3종 운영 풀 미편입:** 설정은 §1.3에서 확정했고 검증용 임시 카드로 실행을 확인했다. 과부하 합성 운영 편입은 §1.8을 따른다. 다른 레인의 해킹5장과 합쳐 현재 운영 풀은30장이다.
- 현재 실제 원천은 디시그망 회복과 과부하 합성 지출이다. 제물, 가속 운전, 시간 금고, 과열 압축은 미구현이다. 시간 금고 중 회복 차단을 포함한 나머지 원천은 각 정책 결정 후 연결한다.
- 검증과 한계: [구현 결과](../../outputs/glitch-reactions-20261103/RESULT.md). 남은 결정은 [TODO 사용자 결정 대기함](../../docs/TODO.md)에만 관리한다.

## 4. 수식·SO 계약

일반 시간 수지: **Δ잔액 = 실제 추가초 합 − 자연 감소초 − 실제 카드 지출초**. 정상 보스당 `30 + 디시그망 등 회복 − 유효 전투초 − 카드 지출`. 금고15초는 회복이 아닌 별도 유예로 제안한다.

| 변수 | 의미 / 범위 |
|---|---|
| R, c | 일반 잔액(유한·0이상), 요청 비용(유한·양수) |
| P, k | 확정 실제 지출 누계(0이상), 보상의 초당 SO계수(0이상·미정) |
| dt | 실제 진행 전투초. 정지/히트스톱 중 진행 없음 |
| a, m | 제물1회 가산(0.02, 2026-11-03 사용자 확정), 유효 결제 횟수(정수0이상) |
| N, H | 소비 일반/과열 물리칸 수(정수0이상) |
| p, b | 감망 등급별 스택 계수 / 기존 카드 배율(SO·런타임 원본) |

- 소비 보상 `k×P`. 정수 식량이면 누적 실수 보상−기지급량으로 지급하고 소수 잔량 보관 제안. 매 거래 내림 금지. k=1 시험 입력에서1초1회와0.1초10회는 보상1로 같음(밸런스값 아님).
- 가속 운전 충분한 잔액 구간: 자연dt, 추가소비0.1dt, Elapsed+=dt. `Advance(dt×1.1)` 금지. 11-04 확정: 끝부분 추가 소모 생략/비살상 분할 없이 동일 비율로 감소한다.
- 제물 `B_sacrifice=m×a`. **[제안]** 별도 양수 런 가산 `(1+B_other+B_sacrifice)`를 공격력 기반 피해에1회 곱하고 승천 P_ascension은 별도 곱셈 유지. a=0.02 시험값5회, 승천0.9면1.10×0.9=0.99. 승천에 직접 덧셈하거나1.02^5로 복리 적용 금지.
- **[현행]** IRunStatModifiers.AttackMultiplier는 승천 배율. 셀/토템/부족/연구 항을 임의로 하나로 재편하지 않는다. B_other에 넣을 기존 양수 버프 분류는 Q14. 공격력 계수 경로 ComputeAttackDamageFrom/본체·드론 일반공격에1회, 고정피해 ComputeDamageFrom 등은 제외. 편차·치명·방어·패널티 기존 횟수 보존. 새 소환도 런 가산 조회.
- 과열 `W=N+7.5H`. 감망 기준식 **강화 공격력×(2+W×p×b)**. 일반2/과열1이면 물리3칸·W9.5. 5와1.5 재적용 금지. 점유·예약과 피해가중치를 분리한다. 등급별 소비상한 적용 단위는 Q10.

**SO-first 제안:** 기존 DroneSelectionEffect의 명시 필드 또는 typed OverdriveCardSettings SO 참조로 비용/확률/유예/압축을 저작한다. 현재 Value 하나에 여러 독립값을 인코딩하지 않는다. 카드 참조 SO를 단일 원본으로 하고 Presets/런타임에 숫자를 복제하지 않는다. 공유 SO에 런 상태 저장 금지.

설명·정보창·드래그 비용은 같은 SO와 런타임 조회값을 사용한다. 기본값과 현재 가산/실효 공속/잔액을 구분하고 하드코딩 숫자 문구 금지. 금고로 무효된 회복은 성공 +초 연출을 내지 않는다.

## 5. 합성 거래와 드래그 UI [제안]

현행 Scripts/Unit/MergeManager.cs의 TryMergeByDrag→MergeTargets는 **OriginalTier**로 다음 등급 객체를 생성한 뒤 재료를 제거하고 PlaceUnitWithEffect를 비동기로 진행한다. true 반환은 실제 배치 완료와 다르다. 앞에 결제1줄을 추가하는 것으로 원자성이 보장되지 않는다.

1. IngameEtc/DragHandler.OnDrag의 FindDropCell→SetDropPreview·IsMergeTarget 판정을 재사용해 MergeManager.GetMergeQuote(제안)를 조회한다. 합성 대상 **위**에 비용, 부족하면 **빨강**, 확인창 없음. SetDropPreview는 같은 칸이면 조기 반환하므로 잔액 변화에도 색/비용을 갱신해야 한다. EndPress/취소/파괴에서 표시 정리.
2. hover는 결제·난수·재료 삭제 없음. 취소/대상 변경 무료. 비용 등급 기준은 미정이며 임시 Legend를 소유등급으로 간주하지 않는다. 정확히 같은 잔액도 위험 빨강으로 표시하는 안은 Q20.
3. 드롭에서 유닛/칸/봉인/스턴/런ID와 최신 SO·잔액 재검증. 견적은 가격 보장이 아니다. 동일 입력 거래ID로 중복 결제 방지. **모든 유효 합성 경로**가 동일 commit 함수 사용.
4. 치명 결제(c>=R)는 재료 제거·결과 생성·합성 보상 없이0초 판정. R<c를 무료 거절로 바꾸지 않는다. 금고 발동해도 **그 합성은 취소**. 실제 지출초·보상 집계 Q12.
5. 살아남는 결제의 확률 실패는 일반 합성 결과/비용 유지. 성공은 통상 결과+1등급. Epic 재료→Legend 통상 합성은 과부하 대상에서 제외하며 시간비용/추가등급 추첨 없이 진행한다(2026-11-03 사용자 확정).
6. 시스템 실패 제안: 로드/프리팹/자리 검증과 결과 준비를 commit 전에 끝내고 준비 객체는 비활성 보관. 재료·지출·배치를 동기 commit에서 확정, 시각 연출만 이후 진행. 준비 실패는 무결제·재료 보존. 기존 비동기 배치 계약을 바꾸므로 구현 검토 필요. 치명 결제 경로는 결과 준비 없이 종결한다.
7. commit 뒤 런 종료로 이미 지불한 시간을 돌려 소비 회복 보상을 만들지 않는다. 배치 시스템 실패·롤백 최종 정책은 Q12. 조용한 재시도로 중복 소환/결제 금지.

MergeSupport/HasMergeKeepsTribe 등 보상은 완료 합성1회에만 발동. 추가 소환은 새 합성이 아니며 비용 재청구 없음.

## 6. 시간 API·상태·DI [초기 제안 보존]

TimeSpendResult는 bool 대신 Paid / SkippedInsufficient / Timeout / VaultEntered / RejectedEnded / Invalid / Duplicate를 구별한다. CanCommitEffect, 요청초/실제차감초, RemainingBefore/After, source, RunId/EncounterId/TransactionId를 담는다. 금고 진입을 성공 합성으로 해석하지 않는다.

### 6.2 단일 0초 판정과 금고

| 상태 | 전이 |
|---|---|
| Normal, 금고 미사용 | 자연/사용자결제0→단일 판정. 금고 없으면 Ended, 있으면 VaultGrace |
| VaultGrace, 금고 사용됨 | 회복 전부 무효, 보스·라운드 지속, 레벨업·승천2택 생략,15초 만료→Ended |
| Ended | 늦은 지급·소비·합성·연출 callback으로 부활하지 않음 |

**현행 구조 충돌:** CombatCountdown.Advance는 잔액 감소→OnAdvanced(도래 효과)→IsRunning이면 OnTimeUp이다. 마지막 틱 처치가 StopTimer하면 시간초과가 생략된다. 승인된0초 즉시 패배를 이미 충족한다고 쓰지 않는다. 마지막 도트 처치·동시 회복 인정 순서는 Q08 사용자 결정 필요. 결정 후 모든 경로가 ResolveZeroReached 하나를 거치고 금고가 최종 OnTimeUp/패배 통지 **전**에 가로챈다.

유예는 일반 잔액0과 별도 GraceRemaining=15로 표현하는 안이다. AddTime(15)로 구현하면 회복 금지·제물·A/J를 잘못 발동하므로 금지. 유예 시계/정지 정책 Q06. 보스 교체의 StopTimer가 유예까지 멈춰 영구 생존하지 않도록 결정된 유예 시계를 별도로 관리한다. 만료는 단일 종료상태를 먼저 고정하고 Wave/보상/합성 대기를 취소한다.

일반 회복·디시그망·처치·디버그를 포함한 모든 시간 추가 진입점은 TimerController의 유예/종료 gate로 통일한다. 차단 회복은 actualAdded=0으로 기록하고 OnTimeAdded·성공 +초 연출은 발행하지 않는 안이다. 처치 기록/알림과 무효+30 표시는 분리한다.

## 12. 시간 지출 로그 확장·실측 (C-04)

현 EndlessRunLog.fight_sec는 Time.time 차이며 공격보류 중 실제 타이머 감소와 다를 수 있다. 과거5처치·음수 종료 CSV는 새 수치 확정 근거로 부족하다. 원문/기존 로그는 보존한다.

제안: 새 schema/version 파일(예 endless-runs-v2.csv)과 거래 로그. 기존 헤더에 새 열 혼합 append 금지. 로그 성공 여부가 게임 진행을 좌우하지 않음.

- 런/조우: schema/build/config revision, RunId/EncounterId/round/boss, 시작·종료 잔액, ElapsedCombatTime 차, 실제시간·Time.time 차, 레벨, 도달/처치 라운드, 종료원인·금고진입/유예 길이.
- 거래: transaction/sequence/source/cardId, requestedSeconds/actualPaidSeconds/actualAddedSeconds/blockedAddedSeconds, before/after, 결과, 일반/유예 상태, 원인별 누계. 자연 감소 별도, 자동 비용 부족으로 생략된 요청은 지출0, 치명 합성의 실제 지출은 Q12 결정에 따름. 금고15는 회복으로 합산 안 함.
- 구성: 유닛/실제·전투등급/강화/연구/카드ID/토템·배치/승천, 소환·합성 결과, 디시그망 공격·스킬·회복, 해킹 생산/초과/압축/백도어/폐기·예약/소비/가중치.
