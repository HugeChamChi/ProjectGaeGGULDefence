# 업그레이드 계정 저장 계약 v1

확정일: 2026-11-01. 런타임 저장소를 AccountResearchSaveStore로 연결했다. 현재 강화는 무료이며 아래 비용 동시 처리 규칙은 추후 유료 강화를 도입할 때의 필수 조건이다. 구현/검증 결과는 upgrade-server-save-result.md를 따른다.

## 저장 위치와 단위

현재 규모에서는 별도 노드별 테이블을 만들지 않고 기존 계정당 1행인 `PlayerData`에 `UpgradeProgressJson` 문자열 컬럼을 추가한다. 재화 차감과 업그레이드 진행을 동일 snapshot에 담아 저장한다. 이렇게 해야 차감만 저장되거나 레벨만 저장되는 구간이 생기지 않고, 강화 1회에 별도 테이블 쓰기가 추가되지 않는다.

컬럼이 없는 기존 계정은 아래 빈 문서로 읽는다. 컬럼이 존재하지만 JSON이 손상됐거나 지원하지 않는 버전이면 강화 변경을 막고 원본을 보존한다.

```json
{
  "SchemaVersion": 1,
  "Trees": [
    {
      "TreeKey": "permanent-main",
      "Entries": [
        { "Id": "attack-power", "Level": 3 },
        { "Id": "stamina-capacity", "Level": 1 }
      ]
    }
  ],
  "LocalImportId": ""
}
```

위 키는 형식 예시이며 실제 값은 현재 ResearchTreeData의 고정 TreeKey와 노드 Id를 사용한다. 파일명, 표시 이름, 번역 문자열, 배열 순번을 ID로 사용하지 않는다.

| 필드 | 계약 |
|---|---|
| SchemaVersion | 저장 형식 버전. 밸런스 수정 때 올리지 않는다. 미지원 버전은 쓰기 차단 |
| Trees | 계정의 영구 강화 트리들. TreeKey 중복 금지 |
| TreeKey | 배포 후 유지하는 트리 고정 키 |
| Entries | 노드별 획득 레벨. Id 중복 금지, 정수 Level >= 0. 0레벨은 생략 가능 |
| LocalImportId | 계정에 연결된 로컬 진행을 1회 이관한 식별자. 서버 확인 전 이관 완료 처리 금지 |

계정 소유자는 BACKND 인증 소유자와 PlayerData 행으로 결정한다. JSON 안의 UID로 권한을 결정하지 않는다. 갱신 버전은 기존 PlayerSaveId를 공유하므로 별도 UpgradeRevision은 두지 않는다.

공격력 합계, 증가율, 비용표, 설명, 아이콘, 선행 조건, 최대 레벨은 저장하지 않는다. 배포된 강화 설정에서 계산한다. 기존 ResearchSaveData의 TreeKey/Entries 형태를 트리 항목에 그대로 대응시킨다. 잠시 차트에서 사라진 노드는 삭제하지 않는다. 최대 레벨이 낮아져도 저장 원값은 보존하고 실제 적용값만 현재 설정에 맞춘다.

## 변경과 저장 순서

1. 로그인된 PlayerData가 로드되고 충돌이 없는지 확인한다. ResearchAccountContext에는 Backend.UserInDate와 같은 검증된 계정 키를 연결한다. 기본 `local` 계정을 실제 로그인 계정으로 추정하지 않는다.
2. 현재 snapshot을 복사하여 선행 조건·최대 레벨·보유 재화를 확인한다. 비용 차감과 대상 노드 레벨 변경을 복사본에 함께 적용한다. 하나라도 실패하면 원본은 바뀌지 않는다.
3. PlayerDataController를 통해 복사본을 교체하고 계정별 저널에 즉시 기록한다. UI는 로컬 반영과 서버 확인 상태를 구분한다.
4. 비용이 드는 강화 구매는 즉시 TrySaveAsync를 호출한다. 무료/일반 상태 변경은 기존 30초 묶음·최대60초 저장에 포함할 수 있다. 연속 요청은 기존 단일 쓰기 큐로 처리한다.
5. 실패하면 동일 snapshot을 재전송한다. 재시도에서 비용 차감이나 레벨 증가를 다시 실행하지 않는다. 호출자 timeout 후에도 실제 SDK 콜백 전에는 쓰기 잠금을 풀지 않는다.
6. 출격과 계정 전환 전에는 강화가 포함된 PlayerData의 서버 확인을 요구한다. 실패하면 진행을 보관하고 전환을 보류한다. 전투 보너스는 확인된 계정 진행으로 복사한다.

충돌 시 로컬/서버 레벨의 최댓값을 자동 병합하지 않는다. 재화 소비가 함께 있으므로 레벨만 합치면 무료 강화 또는 재화 손실이 생긴다. 기존 서버 버전 검사로 충돌을 보존하고 재조회·명시적 복구로 처리한다. 동시 다기기 요청의 원자성은 별도 검증 대상이다.

## 기존 로컬 데이터 이관

- 소유자가 검증된 계정별 로컬 저장만 자동 이관 후보로 삼는다. 현재 `local` 키의 데이터는 소유자를 증명할 수 없으므로 로그인한 첫 계정에 자동 지급하지 않는다. 계정 연결을 명시적으로 결정한 이관 경로가 필요하다.
- 서버 강화가 없고 해당 계정의 로컬 진행이 유효한 경우, 기존 재화를 다시 차감하지 않고 전체 트리를 한 snapshot으로 이관한다. 이관 ID도 함께 저장한다.
- 서버 진행이 이미 있으면 서버를 기준으로 로드하고 로컬 원본을 보존한다. 서로 다른 진행을 덮어쓰거나 max 병합하지 않는다.
- 서버 ACK와 재조회로 이관 ID/진행 일치를 확인한 뒤에만 로컬에 완료 표식을 남긴다. 기존 원본은 즉시 삭제하지 않는다.
- 계정 A의 저널/진행/이관 표식은 계정 B에서 사용하지 않는다. 같은 계정으로 돌아와도 세대 번호로 이전 화면의 콜백을 무효화한다.

## 구현 연결점과 완료 조건

| 현재 코드 | 구현할 연결 |
|---|---|
| PlayerData / BackendGameData | UpgradeProgress 모델 및 JSON 컬럼 왕복 직렬화, 누락 기본값/손상 차단 |
| PlayerDataController | 비용과 레벨의 단일 snapshot 변경 및 기존 저널/버전/재시도 공유 |
| IResearchSaveStore | 계정 PlayerData를 읽는 저장소 구현. 재화를 쓰는 구매는 컨트롤러의 원자적 변경 경로를 사용 |
| ResearchSaveSession / ResearchSaveService | 화면별 세션을 계정 진행에 연결하고 이전 계정의 캐시/콜백 격리 |
| ResearchAccountContext | 로그인/로그아웃 시 검증된 계정 키 연결 |
| RootLifetimeScope | 운영 저장소 등록을 서버 연결 저장소로 교체 |
| ResearchRunBonuses | 출격 시 해당 계정의 확정 진행 사용 |

완료 검사는 기존 로컬 이관 재실행, 손상 데이터, 누락 필드, 트리/노드 중복, 차트에서 제거된 노드 보존, 저장 실패, ACK 유실, 저장 중 추가 강화, 재시작, 계정 A→B→A, 재화와 레벨의 동시 복구를 포함한다. 실제 뒤끝 재조회에서 재화·레벨·PlayerSaveId가 일치해야 한다. 로그인/화면 열기/변경 없는 재저장은 추가 쓰기 0회, 강화 구매는 별도 강화 테이블 없이 공통 snapshot 쓰기만 발생해야 한다.
