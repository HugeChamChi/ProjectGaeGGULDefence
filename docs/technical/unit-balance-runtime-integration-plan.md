# 유닛 밸런스 차트 게임 반영 계획

2026-10-26 구현 진척: **기본 스탯만** `DEV_UnitBaseStats` / `LIVE_UnitBaseStats` 단일 스냅샷으로 연결했다. `UnitBalanceChartLoader`가 로그인 후 선택적으로 다운로드하고 `UnitBalanceSnapshot`이 원본 SO를 보존한 사본을 전투와 강화 화면에 제공한다. 기존 3개 차트 분할 계획의 비용·성장·계정 레벨 연결은 아직 미구현이며 아래 전체 계획의 완료를 의미하지 않는다. 기본 스탯 파일은 기획툴의 「뒤끝 DEV 적용」에서 만든다. `UnitBalanceChartSettings.json`의 UseRemote 기본값은 false이며 실서버 적용 검증은 미완료다. 파일 생성·콘솔 열기·서버 파일 일치 확인은 단계별로 구분한다.

2026-10-25. 상태: 코드 조사에 근거한 구현 제안. 이 문서는 차트 업로드, 게임 코드 연결, 유저 저장 이관을 적용하지 않는다.

## 목표와 전제

기획 툴에서 수정한 유닛 기본 스탯·강화 비용/성장·레벨 보너스를 뒤끝 차트에서 읽어 강화 화면과 실제 전투에 동일하게 반영한다. 처음에는 이를 지원하는 클라이언트 빌드가 한 번 필요하다. 이후 지원하는 숫자와 효과 파라미터 변경은 차트 배포로 반영한다. 새로운 효과 종류/스킬 동작은 클라이언트 코드가 필요하다.

1차 범위는 Units/BaseStats/UpgradeStats다. LevelBonuses는 기획 초안으로 보존하며 고유 효과 구현과 최종 엑셀 구조 확정을 후순위로 미룬다. 별도 트리인 Research 영구 강화, 인게임 식량 강화, 출석/미션은 이번 연결 범위에 넣지 않는다. 유저의 기존 레벨을 기본 스탯이나 공통 차트에 저장하지 않는다.

## 적용한 환경 설정 (2026-10-25)

- 뒤끝 프로젝트는 하나를 유지한다. 유닛 차트는 DEV_Units/DEV_BaseStats/DEV_UpgradeStats와 LIVE_Units/LIVE_BaseStats/LIVE_UpgradeStats로 구분한다.
- `UnitBalanceChartRoute`는 UNITY_EDITOR 또는 DEVELOPMENT_BUILD이면 DEV, 그 외 출시 빌드는 LIVE로 고정한다. 일반 빌드를 테스트 배포하면 LIVE를 선택하므로 테스트 배포는 Development Build를 사용한다. 런타임 전환이나 다른 환경으로의 대체 조회는 없다.
- 이 경로 코드는 아직 유닛 로더에 연결되지 않았다. 기존 EndlessBalance·상점·이벤트 등 다른 차트 경로는 변경하지 않았다.
- MCP `plan_unit_chart_deployment`와 `verify_live_chart_bundle`은 environment 기본값 DEV, 명시적 LIVE를 지원한다. 임의 chartPrefix 인자는 폐지한다. 낮은 수준의 read_live_chart/compare_live_unit_chart는 여전히 지정한 차트명으로 읽기만 한다.
- 기존 묶음의 4개 파일은 로컬 무결성 검사에 사용하되, 업로드 계획과 서버 비교에서는 LevelBonuses를 제외한다. 내보내기 양식 자체는 아직 바꾸지 않았다.
- DEV 검증 후 동일 파일/해시를 LIVE에 수동 반영한다. 계획 파일은 업로드 증빙이나 운영 승인이 아니다. 서버 차트 생성·업로드는 미실행이다.
- 계정·저장 테이블·서버 설정은 공유된다. 테스트는 별도 계정으로 진행한다. 차트 이름 분리는 접근 권한이나 서버 전체 격리를 제공하지 않는다.

## 권장 적용 방식

원본 UnitData SO는 프리팹·아이콘·스킬 구조와 기본값으로 보관한다. 검증을 통과한 원격 밸런스를 읽기 전용 메모리 데이터로 구성하고, 전투 시작 시 실행용 UnitData 복사본에 허용한 스탯만 적용한다. 원본 SO 에셋을 저장하거나 덮어쓰지 않는다. 복사본의 등급별 값이 원본과 독립적인지도 검증한다.

강화 UI는 같은 밸런스 데이터를 읽어 현재/다음 레벨, 최대 레벨, 비용, 보너스 설명을 계산한다. 전투는 시작 시 밸런스 버전과 계정별 강화 레벨을 함께 고정한다. 로비에서 새 밸런스를 읽어도 진행 중인 전투는 끝까지 기존 스냅샷을 사용한다. 복사본은 런 종료 시 정리한다.

## 구현 순서와 완료 기준

### 1. 데이터 단위와 키 확정

- UnitKey와 현재 UnitData/족장 저장 식별자를 대응시킨다. 파일명 변경과 보유 개수를 강화 레벨 변경으로 해석하지 않는다.
- 공격속도 기준은 전투 코드와 같은 초당 공격 횟수로 통일하는 것을 권장한다. 현재 AttackInterval 열 이름/편집기 설명/Presenter 계산을 함께 맞추고 기존 원본 값의 의미를 확인한다. 이름만 보고 기존 숫자를 역수로 바꾸지 않는다.
- MultiplierIncrease/GlobalBonusIncrease를 레벨 2부터 누적하는 계산과 적용 대상 스탯을 명시한다. 동일 배율을 UI와 전투에서 중복 적용하지 않는다.
- DescriptionOnly와 실제 실행 가능한 EffectKey/EffectParams를 구분한다. 첫 단계는 기본 스탯/비용/성장/설명 반영으로 한정하고, 보너스 동작은 지원 효과별로 추가한다.

완료 기준: 대표 유닛의 Lv.1/중간/최대 레벨과 공격속도 환산 결과가 원본 수치와 일치한다.

### 2. 차트 묶음 버전과 배포 검증

- 1차 대상 3개 데이터 차트에 공통 ReleaseKey를 추가하고, 버전/행 수/정규화 내용 해시를 가진 작은 DEV_UnitBalanceRelease/LIVE_UnitBalanceRelease 차트를 별도로 둔다. 아직 미구현이며 파일 바이트 해시와 서버 데이터 내용 해시를 혼동하지 않는다.
- 3개 차트를 업로드/적용한 뒤 Release 차트를 마지막에 적용한다. 현재 exporter/검증기도 이 계약에 맞춰 수정한다.
- 먼저 개발용 차트에서 업로드한 값과 MCP 조회 값을 전부 비교한다. 자동 업로드가 안 되면 콘솔에서 수동으로 업로드/적용한다.

완료 기준: 신·구 파일이 섞인 묶음은 적용되지 않고, 배포 원본과 서버의 키/수치/보상 비용/효과 파라미터가 일치한다.

### 3. 게임용 로더와 메모리 밸런스 구성

- 기존 SDK 게이트웨이 패턴으로 Release → 3개 차트 → Release 재확인 순으로 읽는다. UnitBalanceChartRoute의 환경 선택을 사용하고 Release 이름도 그 환경과 맞춘다.
- 지원 스키마/버전, 중복 키, 숫자 범위, 등급 누락, 단계 누락, 유닛 매핑, 지원 효과를 검증한 뒤 묶음 전체를 한 번에 교체한다.
- 초기 로그인 후 로비 강화 화면을 열기 전에 로드한다. 첫 구현에서는 전투 중 자동 갱신을 넣지 않는다.
- 잘못된 묶음은 신규 적용을 거절하고 이미 검증된 메모리 버전을 유지한다. 최초 로드에 실패하면 해당 강화/출격 준비를 재시도하게 하며 일부 차트나 빈 기본값을 섞어 확정하지 않는다. 영속 오프라인 캐시는 별도 후속 범위다.

완료 기준: 정상 로드 시 버전/행 수가 확인되고, 누락·통신 실패·미지원 버전에서 불완전한 데이터로 시작하지 않는다.

### 4. 강화 화면과 기본 스탯의 전투 반영

- 고정 비용/성장률/최대 레벨/보너스 목록을 차트 조회로 교체한다. 유닛마다 최대 레벨이 다른 경우도 지원한다.
- 기존 UI/프리팹 구조를 유지하면서 표시는 실제 유닛 종류와 데이터 키를 기준으로 계산한다. 목록 위치를 생산 유닛 판별 근거로 사용하지 않는다.
- 원격 기본 스탯을 전투용 데이터 복사본에 채워 공격·스킬 쿨다운·식량·최대 드론 수의 기존 소비 경로가 동일 데이터를 읽게 한다.

완료 기준: 공격력/공격속도/식량 수치 한 개씩을 바꾸면 강화 화면과 실제 전투 측정값이 함께 바뀌며 원본 SO 값은 유지된다.

### 5. 실제 계정 강화 진행 연결

- 미리보기 진행과 실제 계정 진행을 분리한 현재 구조를 유지하고, 실제 유저용 저장 구현을 추가한다. 개발 검증은 격리된 레벨로 먼저 수행한다.
- 강화 레벨은 계정 + UnitKey별로 저장한다. 임시 미리보기 돈/레벨을 계정에 자동 복사하지 않는다. 기존 보유 캐릭터 개수도 레벨로 취급하지 않는다.
- 실제 구매는 서버에서 차트 비용/최대 레벨을 검사하고 재화 차감과 레벨 증가를 같은 작업으로 확정한다. 기존 재화 저장과의 충돌, 재요청, 두 기기 동시 강화를 함께 처리한다.
- 출격 시 확정된 계정 레벨을 전투 배율에 반영한다. Research와 인게임 강화는 기존 계산 위치에서 별도로 적용한다.

완료 기준: 앱 재실행/계정 전환 후 올바른 레벨을 불러오고, 강화 1회에 재화와 레벨이 함께 한 번만 변경되며 실제 전투에 반영된다.

### 6. 고유 레벨 보너스 실행 연결

- 승인한 EffectKey별 실행기를 기존 전투/생산/스킬 이벤트에 연결한다. DescriptionOnly는 설명 표시만 유지한다.
- 도달 레벨의 효과를 전투 시작 시 결정하고 임계 레벨 직전/직후에 검사한다. 효과 설명과 실제 수치를 같은 파라미터에서 만든다.

완료 기준: 쿨타임 감소·추가 생산·해킹 등 각 지원 효과가 조건에 맞게 한 번 적용되며 알 수 없는 효과를 임의로 실행하지 않는다.

## 착수 권장 범위

먼저 1~4단계를 수행해 **기획 수치 → 차트 → 강화 표시 및 기본 전투 스탯**을 연결한다. 이 단계의 레벨별 검증은 격리된 데이터로 진행한다. 실제 재화를 쓰는 유저 강화와 고유 보너스 전투 동작의 완성은 5~6단계까지 완료해야 한다.

최종 검증은 개발 차트에서 정상값/잘못된 값/통신 실패, 동일 레벨 표시·전투 일치, 전투 중 차트 변경, SO 원본 보존, 저장·재화 충돌 및 계정 전환을 포함한다.
