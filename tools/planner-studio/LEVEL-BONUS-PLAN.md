# 레벨 보너스 수신·표시 및 알팡 문구 Excel 관리 계획

2026-10-30 / 계획 단계. 이 문서 작성으로 실행 코드·차트·엑셀·계정 데이터는 변경하지 않는다.

## 목표

1. 사용자가 보고 있는 보너스가 서버의 어느 유닛/레벨 정의인지 화면과 로그로 확인한다.
2. 유닛과 알팡의 보너스 설명·강조·용어 링크를 기획툴/일반 표 Excel에서 관리한다.
3. 설명 데이터와 실제 능력 실행을 분리하되 같은 식별자와 수치를 참조해 불일치를 막는다.

## 현재 확인한 사실과 미확인 증상

- 지난 검사에서 DEV_UnitLevelBonuses 45행은 업로드 엑셀과 일치했고 UnitBonusChart.IsLoaded=true였다. 이는 모든 화면의 표시와 실제 계정의 보너스 해금을 보증하지 않는다.
- UnitBonusChart는 효과 행으로 설명을 자동 조립한다. Excel의 자유 설명/용어 링크 정보는 현재 전송하지 않는다.
- DeckUpgradeBonusView는 `(행 번호+1)*3` 레벨의 설명을 찾아 숫자 강조·고정 문자열 치환을 적용한다. 서버 해금 레벨이 달라지면 대응하지 않는다.
- 보너스 화면의 행 선택은 unitName 비교이며 알 수 없는 이름도 알팡 분기로 들어간다. 이름 변경/신규 유닛에 잘못된 문구가 표시될 위험이 있다.
- 알팡은 화면 호출에서 UnitData=null이므로 하드코딩된 Labels 문구를 사용한다. 원격 보너스 목록 9종에는 알팡이 없다.
- '[해킹]', '[자폭드론]', '[액티브 스킬]'과 특정 알팡 행의 '공격속도 증가'를 코드에서 링크로 바꾼다. 알팡 효과 툴팁의 수치도 별도 코드에 있다.
- 실제 전투 레벨은 PlayerData.UnitLevels에서 읽고 누락 시 1이다. 미리보기 강화 화면의 레벨과 별개여서 화면에서 레벨을 올려도 실제 전투 보너스가 해금되지는 않는다.
- 사용자가 보고한 '못 받는 것 같다'는 현상은 아직 해당 화면에서 재현·원인 확정하지 않았다. 수신 실패로 단정하지 않는다.

## 1단계: 수신부터 표시까지 진단

개발 로그에 다음을 한 줄로 기록한다. 인증 토큰/비밀번호/계정 전체 데이터는 기록하지 않는다.

`ChartName / AppliedFileId / UnitKey / AssetKey / Source(remote|bundled|legacy) / DefinitionCount / MilestoneLevels / AccountLevel / PreviewLevel / UnlockedLevels / RenderedBonusKeys`.

- 현재 선택 유닛과 알팡 각각 검사한다. UnitKey→AssetKey→런타임 사본→화면이 같은 대상을 참조하는지 확인한다.
- 앱 재시작 전/후, 보너스 탭 전환, 다른 유닛 선택 후 재선택을 검사한다.
- 빈 목록/키 불일치/수신 대기/실제 잠금 상태를 다른 상태로 표시한다. 실패를 알팡 예시 문구로 덮지 않는다.
- 기존 5행 고정 레벨 검색을 서버 정의의 정렬된 보너스 목록으로 교체한다.
- 진단이 끝나면 원인과 재현 절차를 기록하고 필요한 최소 수정만 한다.

완료 기준: 서버 정의를 한 곳 수정해 재적용/재시작하면 해당 유닛 화면에서 그 변경과 출처를 확인할 수 있고, 정의 수신과 계정 해금 여부가 구분된다.

## 2단계: 표 형태 규약

기획자가 편집하는 파일은 UnitLevelBonuses.xlsx. 아래 시트로 구성하고 JSON/Base64 셀은 사용하지 않는다. 파일명에 날짜를 넣고 ReleaseKey 열은 넣지 않는다.

### BonusDefinitions — 설명과 해금

| 열 | 역할 |
|---|---|
| BonusKey | 변경하지 않는 보너스 식별자 |
| TargetKind | Unit / Chief |
| TargetKey | 유닛 UnitKey 또는 AlphanChief |
| UnlockLevel | 해금 레벨 |
| DisplayOrder | 표시 순서 |
| DescriptionTemplate | 플레이스홀더가 있는 설명 |
| DescriptionMode | Auto / Template |

### BonusParts — 실제 능력

`BonusKey / PartIndex / EffectType / Stat / ValueMode / Value / CycleId / Every / DamageBonusPercent / ChargeReductionPercent`.

기존 일반 표 효과 계약을 유지한다. EffectType→Enum→명시적인 클래스 factory만 허용한다. 알팡은 기존 실제 족장 효과와 실행 지점을 먼저 대조하고 지원하는 것만 등록한다. 알팡 문구가 존재한다는 이유로 실제 효과가 구현됐다고 처리하지 않는다.

### BonusTextTokens — 용어·수치 참조

| 열 | 역할 |
|---|---|
| BonusKey | 연결할 보너스 |
| TokenKey | 템플릿에서 사용할 토큰 이름 |
| TokenKind | Term / Effect / Value |
| ReferenceKey | 기존 용어 사전 키 또는 효과 키 |
| PartIndex | 수치 참조 대상 Part. Value일 때 사용 |
| ValueField | Value / Every / DamageBonusPercent / ChargeReductionPercent 등 허용 필드 |
| LabelOverride | 비우면 카탈로그 이름 사용 |
| StyleKey | Number / Term / PositiveEffect 등 스타일 키 |

예: 템플릿 `스킬 사용 시 {term:active_skill} 효과로 {value:speed} 동안 {effect:attack_speed} 적용`.

숫자를 문구에도 따로 입력하지 않는다. Value 토큰은 효과 Part의 실제 값을 참조해 %, %p, 초 등의 단위를 붙인다. 구현하지 않은 알팡 효과는 설명 초안으로만 저장하고 게임 배포는 막는다.

### TextStyles — 공통 표현

`StyleKey / ColorHex / Emphasis`. 스타일은 승인한 카탈로그를 선택한다. 기본 숫자 주황, 용어 노랑, 긍정 효과 초록은 현행 표현을 유지한다. 기획자에게 TMP `<link>`/`<color>` 태그를 직접 작성시키지 않는다.

용어 사전/팝업 영상은 기존 TermGlossary와 TermPopup을 재사용한다. Excel에는 사전 식별자만 넣으며 영상·설명 본문을 중복 복제하지 않는다. 알팡 전용 문자열 치환과 고정 툴팁 수치는 제거 대상이다.

## 3단계: 기획툴 편집 화면

- 대상 유닛/족장 → 해금 레벨 → 보너스 선택.
- 능력 탭: 한글 효과 선택, 스탯 선택, 고정값/%/%p, 수치, 여러 Part 조합.
- 설명 탭: 자동 설명 또는 템플릿. '용어 넣기 / 효과 링크 넣기 / 수치 넣기' 버튼으로 토큰 삽입.
- 옆 미리보기에서 색상·링크·잠금 상태를 실제 게임과 같은 토큰 규칙으로 표시한다.
- 미리보기 레벨은 '표시 테스트 레벨'로 명시하고 실제 계정 레벨과 혼동하지 않는다.
- 누락된 용어·미지원 알팡 효과·없는 수치 참조는 행/열을 지정해 오류 표시한다.

## 4단계: 업로드와 게임 연결

- 편집용 다중 시트는 내보낼 때 단일 업로드 시트로 펼친다. `RecordType=Definition|Part|Token|Style`로 구분한다. 모든 값은 일반 열로 남긴다.
- 대상 차트는 기존 DEV_UnitLevelBonuses / LIVE_UnitLevelBonuses를 유지한다. 알팡 정의도 TargetKind로 구분한다.
- 전체 파일 파싱·참조 검증 후 한 번에 설치한다. 잘못된 문구만 무시해 이전 문구와 새 능력이 섞이지 않게 한다.
- 기존 45행 효과 전용 차트는 이전 계약으로 읽는다. 새 구조에서 인식 불가능한 행은 명시적 오류로 처리한다. 기존 기본 설명은 기존 파일을 읽을 때만 자동 생성한다.
- 게임 렌더러는 일반 텍스트를 escape한 뒤 검증된 토큰만 TMP 링크/색상 태그로 변환한다. 임의 rich text는 실행하지 않는다.
- 화면·툴팁·전투가 같은 BonusKey와 Part 값을 참조한다. 유닛 이름과 행 번호에 따른 예외 분기는 제거한다.
