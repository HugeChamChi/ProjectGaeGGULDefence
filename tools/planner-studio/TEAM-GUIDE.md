# GGD 기획 작업실 · 팀 사용 안내

배포 구분: **기획 편집·내보내기용 팀 검증 버전** (2026-10-26).

## 툴에서 DEV 적용하기

왼쪽 **뒤끝 DEV 적용**에서 미션 이벤트 설정 또는 유닛 기본 스탯을 선택하고 **DEV 적용 파일 준비**를 누릅니다. 편집 중이라면 먼저 「수정 저장」하세요. 동일 프로젝트에서 작성·검토용 Excel, 열 규약, 업로드용 단일 시트 `.backend.xlsx`, `deployment.json`을 같은 폴더에 만듭니다. 작성용과 업로드용의 해시를 함께 기록합니다. 업로드용을 직접 편집하지 말고 작성용을 수정한 뒤 다시 준비하세요.

| 선택 | 대상 차트 | 게임의 원격 사용 설정 |
|---|---|---|
| 미션 이벤트 설정 | DEV_MissionEvents | Resources/EventChartSettings.json |
| 유닛 기본 스탯 | DEV_UnitBaseStats | Resources/UnitBalanceChartSettings.json |

**공식 콘솔에서 업로드·적용**을 누르면 툴의 별도 창에 공식 뒤끝 콘솔이 열립니다. 정상 로그인 후 표시된 차트에 준비 파일을 업로드하고 「차트 파일 적용」을 누릅니다. 콘솔 로그인 방식이 내장 창에서 동작하지 않으면 **기본 브라우저로 열기**를 사용합니다. 공개 업로드 API는 확인되지 않아 비공개 콘솔 API로 자동 전송하지 않습니다. 파일 준비는 업로드 완료가 아닙니다.

게임 담당자는 **게임 프로젝트 선택 → 서버 적용 파일 확인**으로 서버의 현재 적용 파일과 준비 파일의 버전·내용 해시를 대조할 수 있습니다. 이 조회는 해당 PC의 Unity CLI, 열려 있는 동일 프로젝트의 Editor/Pipeline, 기존 뒤끝 로그인 세션이 필요합니다. 게임 진행이나 계정 데이터를 쓰지 않습니다. 일치 결과는 `server-verification.json`에 저장하며 실제 플레이 검증과는 구분합니다.

게임 프로젝트의 `Assets/WorkSpace/USW/Resources/` 아래 해당 JSON에서 `UseRemote`를 true로 설정하고 게임 앱 또는 Editor Play를 다시 시작하면 설정을 다운로드합니다. 기본값은 아직 false입니다. Editor/Development Build는 DEV, 일반 출시 빌드는 같은 이름의 LIVE 차트를 읽습니다. **실서버 적용과 실제 플레이 검증은 미완료**이며 LIVE 적용은 DEV 검증 후 수행합니다.

유닛 기본 스탯 파일은 4개 등급의 공격력·공격 속도(회/초)·쿨타임·식량·드론 수를 한 파일에 묶습니다. 원본 SO를 보존한 런타임 사본을 전투와 강화 화면에서 사용합니다. 새 작성용 Excel과 런타임 파일은 공격 속도를 `AttackFrequency`로 명시합니다. 이전 `AttackInterval` 열도 값 변환 없이 읽습니다. 기존 DEV_Units/DEV_BaseStats/DEV_UpgradeStats 파일은 이 로더의 입력이 아닙니다.

이 연결은 **유닛 기본 스탯까지**입니다. 강화 화면의 비용·배율·레벨 저장은 여전히 미리보기 경로이며 계정 강화 구매나 보너스 실행은 연결되지 않았습니다. 기본 설정·튜토리얼·출석 이벤트의 신규 양식 로더, 미션 진행도 서버 저장·복원·보상 지급도 남아 있습니다.

## 실행과 작업 전달

1. ZIP을 모두 압축 해제하고 `GGD-Planner/GGD-Planner.exe`를 실행합니다. Windows용이며 Node·Python·Unity·Excel 설치 없이 실행할 수 있습니다.
2. 설정의 「팀 검증 버전 · 게임 적용 범위」를 확인합니다. 다크 모드도 설정에서 켜고 끕니다.
3. 작업은 PC별 사용자 폴더에 자동 저장됩니다. 다른 팀원에게 전달할 때는 「프로젝트 저장」으로 JSON을 내보내 전달합니다. 받는 사람은 현재 작업을 JSON으로 백업한 뒤 불러옵니다.
4. Excel은 해당 자료의 편집·검사용입니다. 내보내기만으로 서버나 게임이 변경되지는 않습니다.
5. 업데이트는 툴을 종료한 후 새 폴더를 압축 해제하여 실행합니다. EXE 하나만 옮기지 마세요. 기존 PC의 자동 저장은 유지되며 다른 PC로는 자동 이동하지 않습니다.

|---|---|---|
| 기존 밸런스 | 편집·기존 Excel 출력 | 기존 차트 적용 절차로 반영 |
| 유닛 기본 스탯 | DEV 파일 준비·전투/화면 로더 연결 | 실서버 적용·플레이 검증 |
| 유닛 강화·기본 설정·튜토리얼 | 편집·검사·내보내기 | 신규 출력 양식과 실제 게임 로더 연결 |
| 영구강화 | 트리 편집·내보내기 | 별도 ResearchBalance 변환·아이콘 등록·게임 검증 |
| 미션 이벤트 설정 | 편집·업로드 파일 생성 | DEV 차트 업로드·적용 후 게임 검증 |
| 미션 진행·지급 | 세션 내 진행 계산 | 진행도 서버 저장·복원, 수령 상태, 보상 지급 |
| 출석 이벤트 | 편집·내보내기 | 새 출석 이벤트 양식의 게임 연결 |

## 미션 이벤트 DEV 검증

기획 담당자는 실행 지점·데이터 연결·기간·목표·보상을 편집한 후 「Excel 내보내기」를 누릅니다. `MissionEvents.xlsx`는 편집용, `MissionEvents.data.json`은 확인용, **`MissionEvents.backend.xlsx`는 뒤끝 업로드용**입니다. 파일 이름이 비슷하므로 용도를 구분하세요.

서버 적용 담당자는 뒤끝 콘솔의 **DEV_MissionEvents** 차트에 backend 파일을 업로드하고 **적용**합니다. 기존 적용 파일을 기록해 두고 문제가 생기면 이전 파일을 다시 적용합니다. 툴은 콘솔 업로드를 자동 수행하지 않습니다.

게임 담당자는 Unity 프로젝트에서 `Assets/WorkSpace/USW/Resources/EventChartSettings.json`의 `UseRemote`를 true로 설정합니다. Editor 또는 Development Build로 로그인하여 차트 조회와 설정 로드를 확인합니다. 로드 실패는 로그인 초기화 오류로 전달됩니다. 다른 환경이나 로컬 예시로 자동 대체하지 않습니다. 로컬 확인으로 돌아갈 때는 false로 설정합니다.

확인 항목: 일반/어려움 실행 지점 구분, 이벤트 시작·종료 경계, 일일 초기화, 목표 진행, 계정 변경 시 격리. **재접속 복원과 보상 지급은 아직 구현되지 않아 운영 이벤트 지급 용도로 승인할 수 없습니다.** 동봉 예시는 비활성이며 활성화했다고 실제 보상이 지급되는 것은 아닙니다.

DEV 검증을 마친 설정 파일은 담당자와 검증 결과를 기록한 후 동일 파일을 **LIVE_MissionEvents**에 적용합니다. 일반 출시 빌드는 LIVE를 선택합니다. 진행 저장·지급이 완성되기 전에는 운영 이벤트를 활성화하지 않습니다.

## 전달 전 확인 기록

- 의존성 정리 후 기본 기능 29개, 콘텐츠 UI 19개, MCP 16개 검사 통과. 별도로 Unity 컴파일과 미션/유닛 수치·원본 SO 보존 검사 통과.
- 공통 차트 조회·전송 형식, 기능별 런타임, 툴의 화면·파일 준비·서버 대조·콘솔 창을 분리했습니다. 개발 구조는 동봉 「개발 유지보수 안내.md」를 확인하세요.

- 담당자 이름은 아직 지정되지 않았습니다. 팀에서 기획 편집 / DEV 업로드·검증 / LIVE 적용 담당자를 정합니다.
- 툴의 콘텐츠·Excel·미션 검사와 Electron 화면 검사를 수행한 검증 버전입니다.
- Unity에서 이벤트 설정 파싱·DEV 경로 검증 및 뒤끝 로그인·기존 차트 조회를 확인했습니다.
- DEV_MissionEvents 실서버 적용과 실제 플레이 검증은 아직 완료되지 않았습니다.
- 소스나 게임 프로젝트는 이 실행 ZIP에 포함되지 않습니다. 게임 담당자는 이 변경이 포함된 프로젝트 코드도 받아야 합니다.
