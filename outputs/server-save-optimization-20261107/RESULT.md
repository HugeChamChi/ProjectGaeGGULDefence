# 서버 저장 최적화

브랜치: CODEX_ServerSaveOptimization. README의 개발 브랜치 명명 규칙 적용. 기존 미커밋 작업 보존.

## 정책

| 구분 | 전송 |
|---|---|
| 로비 변경 | dirty 문서만 마지막 변경30초/최초 변경60초 상한으로 묶기 |
| 전투 시작 | 기존 입장 비용 예약에 이어 예약 소비/run ID 저장 확인 후 전투 진행 |
| 전투 중 | 자동 배치·정기 저장 중지. 기존 실패 재시도와 명시적 거래 저장 유지 |
| 전투 종료 | 미션·경험치·최고 기록을 반영한 후 공통 dirty flush |
| 나가기/전투 실패/씬 파괴 | 전투 저장 보류 해제 및 남은 계정 dirty 전송. 임시 전투 보상 지급 없음 |
| 백그라운드 | 중복 콜백을 합쳐 dirty flush |
| 복귀 | 60초 미만 계정 재조회 생략. 60초 이상 기존 시간 동기화 및 계정 재조회 |
| 정상 종료 | 더티 저장 시도. OS 강제종료/통신 완료는 보장하지 않음 |
| 로그아웃/계정 전환 | 기존 저장 성공 확인 후 이동하는 경로 유지 |

처치·피해량은 원래 메모리 집계이므로 중복 구현하지 않았다. 이어하기가 없어3분 체크포인트 및 전투 로컬 복구는 추가하지 않았다. 기존 계정 저널은 거래 재시도/응답 유실 복구와 연결되어 있어 보존했다.

## 요청 감소

- 전역 저장에서 Character/Tutorial 호환 매니저를 제외해 같은 문서의 중복 저장 진입 제거.
- 겹치는 flush는 실행을 공유하고, 도중 새 명시적 요청이 오면 dirty를 다시 확인.
- 명시적 저장 후 예약 타이머 취소. 변경마다 토큰을 재생성하지 않고 한 배치의 타이머 재사용.
- 같은 편성 재선택은 dirty/저널/예약 저장을 만들지 않음.
- 최고 기록 한 모드 갱신의 정상 경로는 조회3+쓰기1에서 조회2+쓰기1로 감소. Merge 내부 소유권·충돌·최대값 확인은 유지.
- 정상 기록의 앱 복귀 재조회 생략. 실패/미확정 기록은 기존 재시도 유지.
- 계정 경험치와 미션은 같은 PlayerData 저장에 포함. 최고 기록은 별도 병합이므로 단일 서버 트랜잭션은 아님.
